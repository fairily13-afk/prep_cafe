# 프렙 카페 운영 기록

현재 구현: EPIC 1 판매 입력·수정·삭제와 메뉴 수익성은 사용자 전체 확인으로 완료했다. EPIC 2 운영 비용 입력·수정·삭제, 재료 입고·폐기 기록은 개발자 검사를 통과했고 사용자 전체 확인으로 완료했다. EPIC 3의 실제 재고 입력·종합 손익 화면·전체 재료 잔량 조회·백업·복원은 아직 구현하지 않았다.

## 실행

Node.js 24 환경에서 실행한다.

```sh
npm ci
npm run build
npm run preview
```

주소는 `http://127.0.0.1:5173/#sales`다. 개발할 때는 `npm run dev`를 사용한다. 포트가 이미 사용 중이면 임의로 다른 주소로 넘어가지 않는다. 같은 주소·브라우저 프로필을 유지해야 같은 저장 자료를 읽는다.

운영 비용 화면은 `/#costs`, 재료 입고·폐기는 `/#inventory`다. 화면 이동은 같은 저장 자료를 이용한다. 기존 저장 자료를 처음 EPIC 2로 열 때, 기존 폐기 189건의 평가 금액과 가격 근거를 거래 하나로 보완한다. 실패 시 기존 자료를 유지하며 판매·비용·입고·실제 재고 수량을 샘플로 교체하지 않는다.

## 검사

```sh
npm test
npm run test:e2e
```

브라우저 검사는 설치된 Microsoft Edge를 사용하고 별도 임시 프로필에 기록한다. 사용자 브라우저의 자료를 초기화하지 않는다. 결과와 사용자 확인은 `docs/05_테스트결과.md`에 기록한다.

## 자료 보관

제공된 가상 샘플 JSON만 최초에 한 번 준비한다. 엑셀과 중복으로 합치지 않는다. 이후 기록은 브라우저 IndexedDB에 보관한다. 서버·GitHub에 매장 기록을 전송하지 않는다. 브라우저 자료를 지우면 기록이 사라질 수 있다. 전체 백업·복원은 아직 구현하지 않았으므로 현재는 가상 샘플로 테스트한다.

정식 배포는 후속 EPIC 완료 기준에 포함된다. `vercel.json`은 배포 설정 준비이며, Vercel 계정 연결·접근 보호·실제 배포가 완료됐다는 의미가 아니다. 실제 매장 자료·백업·비밀값을 코드 저장소에 넣지 않는다.
