상태: 사용자 확인 완료. 제안한 3개 EPIC·14개 User Story 구성을 승인받아 저장했다.

기준 문서: `docs/01_PRD.md`, `docs/02_FRD.md`, `docs/03_TRD.md`, `design` 폴더의 시안.

이 문서는 개발과 검사 계획이다. 프로그램 구현·검사·배포가 이미 완료됐다는 의미는 아니다.

### 구현 진행 상태 — 2026-10-12

| 1. 판매 기록과 메뉴 수익성 | S01~S04 구현, 계산·저장 자동 검사 30개와 실제 Edge 검사 7개 통과 | “다 맞는 것 같아 epik2qjs 진행해!”라는 전체 확인 및 다음 EPIC 진행 요청 | **완료 — 사용자 전체 확인** |
| 2. 비용과 재료 변동 기록 | S05~S09 구현, 기존 검사를 포함한 자동 검사 45개·실제 Edge 검사 14개 통과 | “epic2 다 확인 했어”라는 전체 확인 | **완료 — 사용자 전체 확인** |

## 1. 전체 작업 순서와 나눈 이유

**1차 개발은 EPIC 3개, User Story 14개로 구성한다.** EPIC은 함께 완성할 작업 묶음이고, Story는 사용자가 한 가지 목적을 달성하는 기능이다.

PRD·FRD의 범위와 계산 기준을 유지하고, 시안에서 빠진 필수 입력칸과 기능을 보완한다.

| 순서 | EPIC | Story 수 | 먼저 만드는 이유 |
|---|---|---:|---|
| 1 | 판매 기록과 메뉴 수익성 | 4개 | 판매 기록이 메뉴 수익성·손익·재료 사용량의 출발점이다. |
| 2 | 비용과 재료 변동 기록 | 5개 | 운영 손익과 재료 잔량을 완성하려면 비용·입고·폐기 기록이 필요하다. |
| 3 | 손익·재고 확인과 자료 보관 | 5개 | 앞서 쌓은 기록을 종합하고, 실제 재고 확인과 백업·복원까지 연결한다. |
| **합계** | **3개 EPIC** | **14개** | EPIC별 최대 5개 조건을 충족한다. |

판매와 비용의 입력·수정·삭제는 각각 별도 Story로 나눈다. 입고·폐기·실제 재고 기록도 목적과 계산 효과가 달라 따로 구현한다.

초기 자료 읽기, 계산 도구, 저장 기능은 별도 화면만 만드는 작업으로 분리하지 않는다. 첫 Story부터 실제 저장을 구현하고, 필요한 계산을 각 Story에 연결한다. 따라서 첫 EPIC부터 새로고침 후에도 남는 기록과 실제 계산 결과를 확인할 수 있어야 한다.

PRD의 전체 4시간 목표를 유지한다. 계획·화면 설계·개발·검사·배포 시간을 모두 포함하며, Story 개수를 줄였다는 이유로 4시간 완료를 보장하지 않는다. 시간 부족이 예상돼도 필수 계산·저장·복원 검사를 생략해 완료 처리하지 않는다.

## 2. 모든 Story에 적용할 완료 조건

- 기록은 지정 브라우저에 실제 저장되어야 한다. 저장 성공 안내는 저장이 끝난 뒤 표시한다.
- 새로고침과 브라우저 재접속 후에도 기록과 계산 결과가 유지되어야 한다.
- 필수값 누락, 잘못된 숫자·날짜·참조 자료를 검사한다. 저장 실패 시 기존 기록과 작성 중인 입력을 보존한다.
- 연속 클릭으로 같은 기록이 두 번 저장되지 않아야 한다. 다른 탭에서 변경된 기록을 덮어쓰지 않아야 한다.
- 자료가 없거나 계산 근거가 부족한 경우를 실제 0과 구분한다. 계산할 수 없는 수익·잔량을 임의의 숫자로 채우지 않는다.
- 자동 검사와 실제 브라우저 확인을 함께 수행한다. 화면만 표시하거나 임시 가짜 저장으로 완료 처리하지 않는다.

아래 자동 검사는 개발하면서 작성·실행할 검사 항목이다. 현재 프로그램 검사가 끝났다는 의미는 아니다.

## 3. EPIC 1. 판매 기록과 메뉴 수익성

**포함 Story:** S01~S04  
**작업 순서:** 판매 입력 → 메뉴 수익성 조회 → 판매 수정 → 판매 삭제

먼저 판매와 계산을 연결한 뒤, 수정·삭제가 같은 결과에 제대로 반영되는지 확인한다.

### S01. 판매 기록 입력하기

**사용자가 할 수 있는 일**  
판매 날짜, 메뉴, 매장·포장 구분, 수량, 실제 판매 단가, 총 할인액, 총 결제 수수료를 입력하고 저장한다.

**자동 검사**

- 수량·금액과 필수 입력값을 검사하고, 같은 날짜·메뉴·판매 구분의 중복을 차단한다.
- 매출·원가·수수료 계산을 FRD 기준과 대조한다. 원가 근거가 없는 기록은 계산 미완료로 표시한다.
- 초기 샘플이 한 번만 들어가고, 이후 재접속 때 사용자가 입력한 기록을 덮어쓰지 않는지 검사한다.

**화면에서 확인할 행동과 예상 결과**  
판매 한 건을 저장하고 새로고침한다. 목록에 같은 기록이 한 번만 남고, 입력한 할인액·수수료와 계산 결과가 유지된다. 잘못된 수량을 입력하면 저장되지 않고 수정할 항목이 표시된다.

### S02. 판매 기록 수정하기

**사용자가 할 수 있는 일**  
저장한 판매 기록을 찾아 잘못 입력한 내용을 수정한다.

**자동 검사**

- 수량·금액 수정 시 당시 단위 원가를 유지하고 합계를 다시 계산한다.
- 날짜·메뉴·판매 구분 변경 시 FRD에서 정한 범위의 원가와 재료 사용량을 다시 계산한다.
- 중복, 다른 탭의 변경, 저장 실패에서 기존 기록을 보존한다.

**화면에서 확인할 행동과 예상 결과**  
판매 수량을 10개에서 8개로 수정한다. 해당 기록과 메뉴 수익성이 바뀌고, 다른 기록의 당시 원가는 유지된다. 취소하면 원래 기록이 그대로 남는다.

### S03. 판매 기록 삭제하기

**사용자가 할 수 있는 일**  
잘못 등록한 판매 기록을 확인하고 삭제한다.

**자동 검사**

- 삭제한 판매의 매출·원가·수수료·재료 사용 효과가 함께 제거되는지 검사한다.
- 이후 날짜의 실제 재고 기록은 유지한다.
- 삭제 취소·실패 시 기록을 보존하고, 이미 삭제된 기록은 상태를 안내한다.

**화면에서 확인할 행동과 예상 결과**  
판매 한 건의 삭제 대상과 내용을 확인한 뒤 삭제한다. 목록과 메뉴 수익성에서 해당 기록의 영향이 없어진다. 새로고침 후에도 삭제 상태가 유지된다.

### S04. 기간별 메뉴 수익성 확인하기

**사용자가 할 수 있는 일**  
일·월·직접 지정한 기간으로 메뉴별 판매 수량, 순매출, 재료비, 포장비, 결제 수수료, 수익과 수익률을 확인한다. 메뉴 검색·분류·정렬을 사용할 수 있다.

**자동 검사**

- 기간의 시작일과 종료일을 모두 포함한다.
- 순매출에서 재료비·포장비·실제 수수료를 빼는 계산을 검사한다. 수익률은 합계 기준으로 계산한다.
- 매장·포장 원가 차이, 음수 수익, 순매출 0, 원가 누락, 검색 결과 소계와 전체 합계를 검사한다.

**화면에서 확인할 행동과 예상 결과**  
판매를 입력한 날짜로 조회한다. 입력 내용이 메뉴별 결과에 반영된다. 메뉴를 검색하면 해당 결과와 소계가 표시되고, 전체 합계와 구분된다. 원가가 없는 경우 수익을 완성된 값처럼 표시하지 않는다.

**EPIC 1 완료 기준**  
실제 판매를 입력·수정·삭제할 수 있고, 그 결과가 기간별 메뉴 수익성에 반영된다. 재접속 후에도 기록이 유지된다.

## 4. EPIC 2. 비용과 재료 변동 기록

**포함 Story:** S05~S09  
**작업 순서:** 비용 입력 → 비용 수정 → 비용 삭제 → 재료 입고 → 재료 폐기

이 단계에서 종합 손익과 재고 계산에 필요한 기록을 갖춘다. 입고·폐기는 저장한 기록과 잔량 변화를 바로 확인할 수 있어야 한다.

### S05. 운영 비용 입력하기

**사용자가 할 수 있는 일**  
비용이 발생한 기간에 해당하는 날짜, 기존 비용 분류, 부가세 제외 금액을 입력하고 저장한다.

**자동 검사**

- 날짜·분류·금액을 검사한다. 같은 날짜·분류·금액의 기록은 중복 가능성을 확인한다.
- 지급일이 아닌 비용 귀속 날짜로 집계한다.
- 기존 월별 계획을 실제 비용에 다시 더하지 않는다.

**화면에서 확인할 행동과 예상 결과**  
특정 날짜에 비용을 입력한다. 그 날짜의 비용 목록과 합계에 반영되고, 다른 기간에는 포함되지 않는다. 새로고침 후에도 남는다.

### S06. 운영 비용 수정하기

**사용자가 할 수 있는 일**  
저장한 비용의 날짜·분류·금액을 수정한다.

**자동 검사**

- 날짜 변경 시 이전 기간에서 빠지고 새 기간에 반영된다.
- 금액 변경 시 비용 합계를 다시 계산한다.
- 판매 원가와 재료 잔량은 변경하지 않는다.

**화면에서 확인할 행동과 예상 결과**  
비용의 날짜를 다음 달로 변경한다. 이전 달 비용에서 빠지고 다음 달에 나타난다. 변경한 금액이 재접속 후에도 유지된다.

### S07. 운영 비용 삭제하기

**사용자가 할 수 있는 일**  
잘못 등록한 비용을 확인하고 삭제한다.

**자동 검사**

- 해당 실제 비용만 삭제하고, 비용 합계에서 제거한다.
- 월별 계획과 다른 기록을 보존한다.
- 취소·실패 시 기존 비용을 유지한다.

**화면에서 확인할 행동과 예상 결과**  
비용 한 건을 삭제한다. 목록과 합계에서 빠진다. 삭제 확인에서 취소하면 그대로 남는다.

### S08. 재료 입고 기록하기

**사용자가 할 수 있는 일**  
기존 재료를 선택하고 입고 날짜, 기준 단위의 수량, 단위 매입 가격, 공급처를 기록한다.

**자동 검사**

- 재료·공급처·단위와 양수 수량을 검사한다.
- 입고 수량을 잔량에 반영하며, 기존 실제 재고 기록도 계산에 적용한다.
- 입고 금액을 운영 비용에 자동으로 더하거나 과거 판매 원가를 바꾸지 않는다.

**화면에서 확인할 행동과 예상 결과**  
재료를 입고한 것으로 기록한다. 입고 목록과 해당 시점 이후의 잔량에 반영된다. 저장 후 새로고침해도 유지된다.

### S09. 재료 폐기 기록하기

**사용자가 할 수 있는 일**  
재료, 폐기 날짜, 폐기 수량, 사유를 기록한다.

**자동 검사**

- 입력한 양수 수량을 폐기 감소량으로 한 번만 적용한다.
- 폐기 날짜의 유효한 가격으로 폐기 비용을 계산한다.
- 가격 누락은 손익 계산 미완료로 표시한다. 잔량이 음수가 되면 경고하며 임의로 0으로 바꾸지 않는다.

**화면에서 확인할 행동과 예상 결과**  
재료를 폐기한 것으로 기록한다. 잔량이 감소하고 폐기 평가 금액이 표시된다. 가격 근거가 없으면 계산할 수 없는 이유가 나타난다.

**EPIC 2 완료 기준**  
실제 비용을 입력·수정·삭제할 수 있다. 입고·폐기를 저장하면 기록 목록과 계산된 잔량에 반영되고, 폐기 비용을 손익에 사용할 수 있다. 모든 기록이 재접속 후 유지된다.

## 5. EPIC 3. 손익·재고 확인과 자료 보관

**포함 Story:** S10~S14  
**작업 순서:** 실제 재고 기록 → 운영 손익 조회 → 재료 잔량 조회 → 전체 백업 → 전체 복원

앞선 기록을 종합해 핵심 흐름을 완성하고, 백업과 복원으로 자료를 보관할 수 있게 한다.

### S10. 마감 시 실제 재고 기록하기

**사용자가 할 수 있는 일**  
날짜와 재료를 선택해 마감 시 직접 센 실제 재고량을 기록하고, 계산상 재고와 차이를 확인한다.

**자동 검사**

- 실제 재고 0을 허용하고 음수와 같은 날짜·재료의 중복 실사를 차단한다.
- 실제 수량을 그날의 마지막 잔량으로 적용한다. 차이 수량을 다시 더해 이중 반영하지 않는다.
- 과거 판매를 수정해도 이후 실사 수량을 유지한다. 실사 차이를 폐기 비용으로 자동 처리하지 않는다.

**화면에서 확인할 행동과 예상 결과**  
계산상 1,000g인 재료의 실제 재고를 900g으로 기록한다. 차이는 −100g, 해당 날짜 마감 잔량은 900g으로 표시된다. 과거 판매를 수정해도 입력한 실제 수량은 유지된다.

### S11. 기간별 운영 손익 확인하기

**사용자가 할 수 있는 일**  
같은 조회 기간의 순매출, 판매 재료비·포장비·수수료, 운영 비용, 폐기 비용과 운영 손익을 확인한다.

**자동 검사**

- FRD의 운영 손익 계산식을 검사한다.
- 재료 매입액 전체와 비용 계획을 추가로 빼지 않고, 재고 차이 비용도 임의로 넣지 않는다.
- 음수 손익, 순매출 0, 계산 근거 누락과 기간 밖의 기록을 검사한다. 계산 중간값을 먼저 반올림하지 않는다.

**화면에서 확인할 행동과 예상 결과**  
판매·비용·폐기를 기록한 기간을 선택한다. 각 항목과 최종 손익이 연결된다. 계산 근거가 부족하면 확인 가능한 합계와 미완료 이유가 구분되고, 재고 차이 비용의 제외 여부가 안내된다.

### S12. 조회 종료일의 재료 잔량 확인하기

**사용자가 할 수 있는 일**  
조회 종료일 기준으로 재료별 잔량, 단위, 최근 실사·입고와 재고 차이를 확인하고 재료를 검색한다.

**자동 검사**

- 시작 재고·입고·판매 사용량·폐기·실사를 날짜 순서대로 반영한다.
- 하루의 실사는 그날 변동 이후에 적용하고, 일별 잔량을 기간 합계로 더하지 않는다.
- 매장·포장별 사용량, 음수 잔량, 시작 재고·사용량 근거 누락을 검사한다.

**화면에서 확인할 행동과 예상 결과**  
조회 종료일을 바꾼다. 그날까지의 기록으로 잔량이 바뀐다. 실제로 센 수량과 기록으로 계산한 수량이 구분되고, 계산 불가나 음수 잔량은 이유와 함께 표시된다.

### S13. 전체 자료 백업하기

**사용자가 할 수 있는 일**  
현재 저장된 전체 자료를 하나의 JSON 백업 파일로 내려받는다.

**자동 검사**

- 기록·기준 자료·당시 원가와 근거·설정·버전 정보가 빠짐없이 포함된다.
- 저장하지 않은 입력은 포함하지 않는다.
- 파일 내용과 현재 저장 자료의 종류별 개수·값을 대조한다. 백업 실패로 기존 자료가 바뀌지 않는다.

**화면에서 확인할 행동과 예상 결과**  
백업을 실행해 파일이 내려받아지는지 확인한다. 현재 기록을 포함하는 파일이 생긴다. 프로그램은 다운로드 요청 결과를 안내하되, 파일이 사용자의 디스크에 남았다고 임의로 보장하지 않는다.

### S14. 전체 자료 복원하기

**사용자가 할 수 있는 일**  
프로그램의 전체 백업 파일을 선택하고 검사 결과를 확인한 뒤, 현재 자료를 백업하고 전체 자료를 교체한다.

**자동 검사**

- 파일 형식·지원 버전·기록 개수·중복·참조 관계·단위를 검사한다.
- 새 자료 전체가 준비된 뒤 한 번에 전환한다. 실패·취소 시 기존 자료를 보존한다.
- 백업→변경→복원 후 기록 수, 당시 값, 손익과 잔량이 원래 결과와 같은지 검사한다.

**화면에서 확인할 행동과 예상 결과**  
백업 후 판매를 변경하고 원래 백업을 복원한다. 교체할 자료를 확인하고 현재 자료의 백업을 받은 뒤 복원하면 원래 기록·손익·잔량으로 돌아온다. 손상된 파일을 선택하면 복원을 막고 기존 자료를 유지한다.

**EPIC 3 완료 기준**  
실제 브라우저에서 다음 흐름을 끝까지 확인한다.

**판매 입력 → 메뉴 수익성 → 운영 손익 → 재료 잔량 → 재접속 → 백업 → 기록 변경 → 복원**

이후 GitHub 코드 보관과 Vercel 배포를 완료하고, 고정 운영 주소에서 같은 흐름과 접근 보호를 확인한다. 실제 매장 기록·백업·접근 비밀값이 코드나 배포 파일에 포함되지 않는지도 검사한다. 배포 계정과 운영 주소는 실제 연결 단계에서 확인한다.

## 6. 이번 계획에 포함하지 않는 기능

PRD의 2차 범위인 엑셀 양식·가져오기, 예상 손익, 발주량, 추가 기간 바로가기, 기준 자료 편집, 반복 비용, 여러 사용자·기기 공유, 자동 백업은 이번 Story에 포함하지 않는다. 시안의 POS 연동·증빙 첨부 등 미승인 기능도 추가하지 않는다.
