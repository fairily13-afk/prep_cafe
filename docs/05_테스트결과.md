# 05. 테스트 결과

## 1. 현재 상태

- 기록일: 2026-10-12, 한국 시간 기준.
- 현재 작업 범위: EPIC 2 ‘비용과 재료 변동 기록’ S05~S09 사용자 전체 확인 및 완료 기록.
- 개발자 검사: 기존 판매 검사를 포함한 계산·저장 자동 검사 45개 통과, 실제 Edge 검사 14개 통과, TypeScript 검사·배포용 빌드 통과.
- 사용자 확인: **EPIC 1에 대한 “다 맞는 것 같아 epik2qjs 진행해!”라는 전체 확인과 EPIC 2 진행 요청을 받았다.** 개별 결과가 없는 검사는 사용자 통과로 바꾸지 않는다.
- EPIC 1 완료 여부: **완료 — 사용자 전체 확인.**
- EPIC 2: 개발자 검사 통과, 사용자 “epic2 다 확인 했어” 전체 확인으로 완료. EPIC 3 미착수. GitHub main 업로드 완료, Vercel 배포 미실시.

개발자 검사 결과와 사용자 확인 결과를 구분한다. 사용자의 실제 답변 없이 ‘사용자 통과’ 또는 ‘EPIC 완료’로 기록하지 않는다. 한 번에 한 확인 항목을 안내하고, 문제가 나오면 수정·재검사 후 해당 항목부터 다시 확인한다. 사용자 확인이 끝나기 전 다음 EPIC을 구현하지 않는다.

## 2. 검사 환경과 실행 방법

- Windows, Node.js 24.19.0.
- React 19.3.0, Vite 8.3.4, TypeScript 7.0.2, idb 8.0.4, decimal.js 10.6.0, Zod 4.6.5.
- 버전은 `package.json`·`package-lock.json`에 고정했다. 별도 재현 폴더에서 `npm ci --ignore-scripts` 설치를 확인했고 설치 도구가 보고한 취약점은 0건이었다. 이것만으로 제품 전체의 보안 검사가 완료됐다는 뜻은 아니다.
- 계산·저장 자동 검사: `npm test` — Vitest, 저장 명령 검사는 fake-indexeddb 사용.
- 실제 브라우저 검사: `npm run test:e2e` — 배포용 빌드 후 Playwright로 설치된 Edge 실행. 실제 IndexedDB와 새로고침·별도 탭을 검사했다.
- 브라우저 자동 검사마다 별도 임시 프로필을 사용했다. 사용자가 직접 확인할 Edge 프로필의 기록과 구분된다.
- 사용자 확인 주소: `http://127.0.0.1:5173/#sales`. 테스트 중 같은 주소·같은 Edge 프로필을 유지한다. `localhost`나 다른 포트는 별도 보관함이 될 수 있다.

### 3.3 화면·속도·빌드 확인

- 시안의 초록 계열, 카드·표·입력 영역, 로컬 글꼴을 반영했다. POS·예상치·발주·임의 메뉴 등급 등의 제외 기능을 넣지 않았다.
- 데스크톱·모바일 캡처를 직접 확인했다. 넓은 표는 표 안에서 가로 이동하며, 작은 화면에서는 입력 영역이 아래로 배치된다.
- 측정한 초기 준비부터 화면 표시까지 3,288ms, 일자 변경·조회·결과 확인 전체 동작 256ms였다. 브라우저 조작·대기를 포함한 값이며, 순수 계산 시간과 구분한다. 이번 초기 로딩은 TRD의 5초 목표 안에 들었다.
- TypeScript 검사와 배포용 빌드가 통과했다. 가상 샘플의 별도 초기 자료 파일 약 2.1MB에 대해 빌드 크기 경고가 있다. 샘플은 기존 저장 자료가 없을 때 필요에 따라 읽으며 실제 기록 업로드 기능이 아니다.
- TRD의 모든 성능 목표를 이번 EPIC에서 측정했다고 처리하지 않는다. 백업·복원 및 확장 자료 검사는 해당 기능 구현 후 수행한다.

### 3.4 검사 중 보완한 사항

- 저장 취소 오류가 처리되지 않은 채 남던 검사 경로를 보완하고, 저장 실패 거래가 취소되는지 재검사했다.
- 판매 구분 선택칸의 접근성 이름을 명확히 해 브라우저 검사와 보조 도구에서 정확히 찾을 수 있도록 했다.
- 판매 기록 없는 미마감 기간의 요약·메뉴 결과를 확정된 0으로 표시하지 않도록 보완했다.
- 위 수정 후 계산·저장 검사와 전체 Edge 검사를 다시 실행해 통과했다. 초기 실패를 최종 통과 결과로 숨겨 기록하지 않는다.
