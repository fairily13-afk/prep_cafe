# 카페 운영 기록 프로그램 제품 요구사항 문서(PRD)

- 작성일: 2026-10-12
- 상태: 1차 제품 요구사항 정리 완료. 개별 답변과 ‘모두 추천으로 해줘’ 요청에 따라 추천 운영 범위를 채택했다. 계산식·화면 설계·기술·상세 동작은 후속 설계 대상이다.
- PRD는 무엇을 만들고 왜 필요한지 정리하는 문서다.
- 이 문서는 계산식, 화면 디자인, 기술 선택, 상세 동작, 코드를 정하지 않는다.
- ‘확인된 사실’, ‘사용자 요청’, ‘제안’, ‘미정’을 구분한다. 제안은 합의된 요구사항이 아니다.

## 1. 목적과 대상

**사용자 요청:** 카페의 판매·재고·비용 기록을 관리하고 메뉴별 수익성, 기간별 실적과 예상 손익, 부족한 재료와 필요한 발주량을 확인하는 웹 프로그램.

**확정된 사용 범위:** 한 매장의 기록을 사용자 한 사람이 한 기기에서 입력·관리·조회한다. 해당 기기에서 웹 프로그램을 이용하고 기록을 보관하는 방향을 채택한다. 여러 직원의 동시 사용, 여러 기기 간 기록 공유, 인터넷 공개 서비스는 1차에 포함하지 않는다. 구체적인 실행·저장 기술은 후속 설계에서 정한다.

**핵심 흐름:** 판매 기록 입력 → 메뉴별로 남는 금액 확인 → 같은 기간의 손익 확인 → 재료 잔량 확인.

비용과 재고 기록도 이 흐름에 연결한다. **확정된 메뉴 수익성:** 메뉴 판매에서 재료비·포장비·결제수수료를 고려해 남는 금액을 본다. 임차료·인건비 등 매장 운영비는 메뉴별로 나누지 않고 매장 전체 손익에서 확인한다. **확정된 매장 손익:** 판매에 사용된 재료비·포장비·결제수수료, 임차료·인건비 등 운영비, 폐기한 재료 비용을 고려해 매장 전체에서 남거나 손해 나는 금액을 본다. 재료 구매대금 전체를 추가 비용으로 넣어 사용·폐기 재료 비용과 중복시키지 않는다. **확정된 비용 반영 시점:** 실제 납부일이 아니라 비용이 해당하는 운영 기간에 반영한다. 실제 재고 차이는 1차에서 수량 조정과 차이 확인에 사용하며, 원인을 확인하지 않은 차이를 자동으로 폐기 비용으로 취급하지 않는다. 따라서 1차 손익에는 원인 미확인 재고 차이의 금액 영향이 포함되지 않는다. 구체적인 가격 적용·계산 방법은 후속 설계 대상이다.

## 2. 자료에서 확인된 사실

### 2.1 출처와 기간

- 확인 자료: `데이터/데이터설명.md`, `데이터/매장운영데이터.xlsx`, `데이터/매장운영데이터.json`.
- 직접 구성한 가상 매장 ‘프렙 카페’의 샘플이다. 실제 매장 거래를 검증한 자료가 아니다.
- 기록 기간은 2025-07-01부터 2026-09-18 마감까지다. 영업달력은 2026-09-30까지 있다.
- 금액은 원이며 부가세를 제외한다. 재료 수량 단위는 g·ml·개다.
- 엑셀과 JSON은 같은 기록의 두 형식이다. 두 파일을 별도 거래 자료로 합치면 안 된다.
- JSON의 `settings`는 비어 있다. 앞으로 적용할 운영 기준이 합의되어 있다는 근거가 없다.

### 2.2 기록 종류

엑셀의 실제 시트와 JSON의 기록 수·항목을 확인했다. 엑셀에는 아래 자료 외에 안내용 `데이터안내` 시트가 있다.

| 기록 | 수 | 주요 내용 | 기획에서의 쓰임 |
|---|---:|---|---|
| 공급사 | 3 | 공급사 번호와 이름 | 재료 공급처 확인 |
| 재료 | 11 | 단위, 구매용량, 최초가격, 납기·안전재고 일수 | 재료 잔량과 향후 발주 참고 |
| 메뉴 | 8 | 이름, 기준 판매가, 분류, 레시피 버전 | 판매 대상을 구분 |
| 레시피 | 22 | 메뉴 한 개의 재료 사용량, 적용 채널 | 판매와 재료 사용을 연결 |
| 재료가격이력 | 33 | 적용 시작일, 구매가격, 구매용량 | 시기별 원가 자료 |
| 영업달력 | 457 | 영업 여부, 마감 여부, 날씨, 메모 | 실적의 기록 완료 여부 확인 |
| 판매기록 | 6,112 | 날짜, 메뉴, 채널, 수량, 당시 가격, 할인, 순매출, 수수료, 당시 개당 원가 | 메뉴 실적·수익성의 근거 |
| 초기재고 | 11 | 첫날 영업 시작 전 수량 | 재료 잔량의 출발점 |
| 재고기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건 | 재료 변동과 실제로 센 수량 확인 |
| 월비용계획 | 120 | 월별 비용 항목과 금액 | 비용 계획과 향후 전망의 자료 |
| 비용기록 | 3,560 | 날짜별 비용 항목·금액·배분 기준 | 기간별 운영 비용의 근거 |
| 자료정보 | 10 | 매장, 출처, 기간, 통화 | 자료의 범위 설명 |

판매는 날짜·메뉴·판매채널별 집계이며 주문 한 건을 뜻하지 않는다. 채널은 매장과 포장이다. 메뉴·재료·공급사 번호는 서로 연결되는 대상을 식별한다.

비용 항목은 임차료, 인건비, 사업주 부담 보험료, 수도광열비, 관리비, 통신·소프트웨어, 광고비, 소모품·청소비다. 제공된 비용기록은 모두 ‘월비용 일할 배분’, 즉 월 비용을 날짜별로 나눈 기록이다. 개별 결제 영수증 기록으로 해석하면 안 된다.

판매·재고·비용의 기록 번호 중복과 날짜·메뉴·채널이 같은 판매 중복은 확인되지 않았다. 판매·레시피·재고·가격이력에서 존재하지 않는 메뉴 또는 재료 번호를 참조하는 기록도 확인되지 않았다. 이 확인은 모든 운영상 정확성을 보증하는 검사는 아니다.

### 2.3 기획할 때 주의할 점

1. **중복 집계:** 엑셀과 JSON은 한 자료다. 월비용계획과 일별 비용도 같은 비용을 다른 단위로 표현했으므로 별도 지출처럼 더하지 않는다.
2. **과거 기록 보존:** 당시 단가·원가·수수료는 과거 기록이다. 현재 가격을 바꿨다는 이유로 과거 수익성이 바뀌는 문제를 피해야 한다. 채택한 방향은 당시 기록 보존과 명시적 오류 수정이며, 새 기록의 구체적인 원가 적용 방식과 과거 수정의 상세 처리는 후속 설계에서 정한다.
3. **수량과 가격의 의미:** 구매가격은 구매용량 전체의 가격이고 레시피는 메뉴 한 개의 사용량이다. 서로 다른 단위를 섞지 않는다. 포장 채널에만 쓰는 재료가 있다.
4. **재고의 의미:** 입고는 양수, 폐기는 음수, 실사조정은 양수 또는 음수다. 기록으로 추정한 잔량과 실제로 센 수량은 구분한다. 채택한 운영 기준은 마감 때 실제로 센 수량에 잔량을 맞추고 차이 기록을 보존하는 것이다. 기존 실사조정과 실측수량을 각각 별도 재고 증감으로 중복 반영하지 않는다.
5. **미완료 기간:** 미래의 미마감 날짜를 매출 0으로 해석하지 않는다. 자료가 일부만 있는 연간·반기·분기 결과를 완전한 기간의 실적으로 오해하지 않도록 한다.
6. **빈칸:** 빈칸과 0은 의미가 다르다. 빈칸은 미입력 또는 해당 없음일 수 있다.
7. **예측과 부족 판단:** 납기·안전재고 일수는 영업일 기준이다. 이 값이 있다는 이유만으로 발주 정책이 확정된 것은 아니다. 예상 손익·부족 판단·권장 발주량에는 별도의 사용자 결정이 필요하다.

## 3. 확정된 1차 범위와 2차 확장 제안

MVP는 처음 만들어 실제 사용 흐름을 확인할 최소 기능이다. 사용자는 2026-10-12에 핵심 흐름 우선·혼자 한 기기 사용을 선택하고, 남은 기획 결정은 추천안으로 진행하도록 요청했다. 아래 1차 제품 범위와 5절의 운영 방향을 채택한다. 2차는 이후 구현할 후보이며 이번 요청으로 개발하거나 계산 기준을 확정한 사항은 아니다. 기획·화면 설계·개발·검사·배포를 포함한 4시간 목표를 유지한다.

| 사용자 요구 | 확정된 1차 범위 | 2차 확장 제안 |
|---|---|---|
| 판매 기록 입력·수정·삭제 | 기존 메뉴의 일자·메뉴·채널별 판매 기록 관리 | 주문별 기록, 복잡한 환불·취소 관리 |
| 메뉴별 수익성 | 재료비·포장비·결제수수료를 고려한 메뉴별 수익성과 판매 실적 확인 | 수익성 등급, 가격 변경 비교, 고정비의 메뉴별 배분 |
| 기간 실적·손익 | 일·월 조회와 시작일·종료일을 지정한 기간 조회 | 주·분기·반기·연간을 바로 선택하는 조회, 기간 비교 |
| 예상 손익 | 1차에서 제외, 2차로 이관 | 사용자가 합의한 전망 기준에 따른 예상 손익 |
| 비용 입력·수정·삭제 | 날짜별 비용 기록 관리와 실제 기간 손익 연결 | 월 계획 편집, 계획 대비 실적, 반복 비용 관리 |
| 입고·폐기·실제 재고 기록 | 기존 재료의 입고·폐기·실제 재고 기록과 잔량 확인 | 재고 변동 상세 분석, 재고 차이 원인 관리 |
| 부족한 재료 확인 | 기록상 잔량과 실제로 센 수량 확인까지 포함 | 부족 기준을 정한 경고와 소진 예상 시점 |
| 발주량 참고 | 1차에서 제외, 2차로 이관 | 권장 발주량과 공급사별 참고 목록 |
| 엑셀 양식 내려받기·가져오기 | 1차에서 제외, 2차로 이관. 첨부 샘플은 초기 자료로 사용 | 판매·비용·재고 입력 양식과 작성한 기록 가져오기 |
| 저장·백업·복원 | 기록을 계속 보관하고 전체 기록을 백업·복원 | 여러 기기 공유, 자동 백업, 백업 이력 |
| 메뉴·재료·레시피·가격 관리 | 제공된 8개 메뉴·11개 재료 등 기준자료 활용 | 기준자료 추가·수정과 변경 이력 관리 |

기간 지정으로 분기·반기·연간에 해당하는 날짜를 조회할 수 있지만, 이를 각 기간의 전용 조회 기능을 구현한 것으로 표현하지 않는다. A안 선택에 따라 엑셀 양식·가져오기, 예상 손익, 권장 발주량은 2차로 이관한다. 1차는 재료 잔량 확인까지 제공하며 부족 경고와 소진 예상도 2차 범위로 둔다.

### 3.1 1차 핵심 요구사항

- **R01 초기 자료:** 제공 자료를 한 번의 자료로 이용한다. 기간·출처·단위를 알 수 있어야 한다.
- **R02 판매 관리:** 판매 기록을 직접 입력·수정·삭제하고 결과를 확인할 수 있다. 과거 기록은 당시 가격·원가·수수료를 보존하고, 명시적으로 고친 내용만 변경한다. 새 기록은 판매 당시 실제 가격·할인·수수료와 해당 시점의 기준자료를 근거로 한다. 필요한 값이 없으면 0으로 간주하지 않고 결과가 미완성임을 알 수 있어야 한다.
- **R03 메뉴 수익성:** 같은 조회 기간의 메뉴별 판매 실적과 재료비·포장비·결제수수료를 고려해 남는 금액을 확인할 수 있다. 임차료·인건비 등 매장 운영비는 메뉴별로 나누지 않는다.
- **R04 비용과 손익:** 비용을 직접 입력·수정·삭제하고 실제 납부일이 아니라 비용이 해당하는 운영 기간의 매장 실적과 손익에 연결한다. 판매에 사용된 재료비·포장비·결제수수료, 임차료·인건비 등 운영비, 폐기한 재료 비용을 포함한다. 재료 구매대금 전체를 사용·폐기 재료 비용에 추가하여 중복 반영하지 않는다. 월 계획과 일별 기록도 중복 비용으로 취급하지 않는다. 기존 일별 비용 자료는 이미 기록된 귀속 기간의 의미를 유지한다. 월 비용을 날짜별로 나누는 방법과 폐기 재료의 가격 적용 기준은 후속 설계에서 정한다.
- **R05 재료 잔량:** 입고·폐기·실제 재고를 기록하고 재료별 단위·기준 시점을 포함한 잔량을 확인한다. 마감 때 실제로 센 수량에 잔량을 맞추고 차이 기록을 남긴다. 실제로 세지 않은 시점의 잔량은 기록에 따른 추정치로 구분한다. 과거 판매·재고 기록을 수정해도 실제로 센 기록 자체를 임의로 바꾸지 않는다.
- **R06 기간 조회:** 일·월·지정 기간을 조회하고 기록이 완료된 범위를 알 수 있다.
- **R07 보관:** 사용자 한 사람이 같은 기기에서 작업을 마친 뒤 다시 이용해도 기록을 확인할 수 있다. 기록은 이용 기기에 보관하는 방향으로 한다. 구체적인 저장 기술은 후속 설계에서 정한다.
- **R08 백업·복원:** 판매·비용·재고 기록과 이를 해석하는 메뉴·재료·레시피·가격이력·달력 등 기준자료 및 운영 설정을 전체 수동 백업으로 따로 보관하고 되살릴 수 있다. 복원은 백업 시점의 전체 자료로 돌아가는 방식이며 기존 자료와 합치지 않는다. 복원 전 현재 자료도 백업으로 보존할 수 있어야 한다. 백업 파일 형식과 상세 복원 절차는 후속 설계에서 정한다.

상세 입력 항목, 버튼 동작, 오류 처리 순서, 저장 형식 등은 후속 설계에서 정한다. 기준이 합의되지 않은 결과를 이미 계산 가능한 것으로 표시하지 않는다.

### 3.2 1차 완료를 판단하는 기준

다음은 결과 중심의 검사 기준이며 상세 검사 절차나 계산식은 후속 단계에서 정한다.

| 확인할 상황 | 기대 결과 |
|---|---|
| 기존 메뉴의 판매를 새로 입력 | 해당 기간의 메뉴 실적·수익성·매장 손익·재료 잔량이 합의된 기준에 맞게 연결됨 |
| 판매를 수정하거나 삭제 | 관련 결과에 이전 기록이 중복되거나 남지 않음 |
| 비용을 입력·수정·삭제 | 실제 납부일이 아니라 해당 운영 기간의 손익에 반영되고 월 계획과 중복되지 않음 |
| 입고·폐기·실제 재고를 기록 | 재료별 단위와 기준 시점이 명확하며 합의한 재고 기준에 맞는 결과를 확인함 |
| 재료 폐기를 기록 | 잔량과 매장 손익에 폐기 영향을 반영하고, 판매에 사용한 재료 비용·구매대금과 중복하지 않음 |
| 마감 때 실제 재고가 기록상 잔량과 다름 | 실제 수량을 마감 잔량에 반영하고 차이 기록을 남기며 원인 미확인 차이를 폐기 비용으로 자동 반영하지 않음 |
| 일부만 마감된 기간을 조회 | 완료된 기록 범위를 알 수 있고 미래 날짜를 실제 매출 0으로 오해하지 않음 |
| 저장 후 다시 이용하고 백업을 복원 | 같은 기기에서 기록을 확인하고 백업 시점의 기록·기준자료·설정을 되살릴 수 있으며 복원 전 자료도 보존할 수 있음 |
| 배포된 프로그램에서 핵심 흐름 수행 | 판매 입력부터 수익성·손익·잔량 확인까지 이어서 사용할 수 있음 |

## 4. 4시간 구현 계획 제안

4시간은 기획·자료 검토·PRD 정리부터 화면 설계·개발·검사·배포까지 포함하는 전체 작업 목표다. 현재 문서 작성도 기획 단계에 해당한다. 이미 수행한 기획 시간을 제외하고 추가 4시간으로 해석하지 않는다. 실제 소요 시간은 작업 시 기록하며, 아래 시간은 단계별 목표 배분이다. 배포의 완료 범위는 이용할 한 기기에서 웹 프로그램을 실행하고 핵심 흐름을 확인할 수 있는 상태다.

| 단계 | 목표 시간 | 산출물 또는 완료 상태 |
|---|---:|---|
| 기획 | 20분 | 합의된 핵심 범위와 미정 목록 정리 |
| 화면 설계 | 20분 | 핵심 흐름에 필요한 화면 구성안 |
| 개발 | 145분 | 1차 핵심 흐름과 기록 보관·백업·복원 |
| 검사 | 40분 | 입력·수정·삭제의 결과 연결과 보관·복원 확인 |
| 배포 | 15분 | 이용 기기에서 실행·접속하고 핵심 흐름 확인 |
| 합계 | 240분 | 4시간 |

한 매장·혼자 한 기기 사용·기존 기준자료·제한된 조회를 전제로 한 목표이며 보장된 견적은 아니다. 여러 기기 공유, 직원별 권한, 임의 형식 엑셀 가져오기는 1차 범위 밖이다. 시간이 부족하면 사용자와 2차로 옮길 기능을 정한다. 핵심 흐름의 검사와 배포를 생략해서 범위가 완료됐다고 처리하지 않는다.

## 5. 결정 현황과 채택한 추천안

2026-10-12에 사용자는 1차 범위, 사용 인원·기기, 메뉴 수익성, 비용 반영 시점, 폐기 비용 포함을 차례로 선택했다. 이어서 **‘모두 추천으로 해줘’**라고 요청하여 남은 1차 기획 결정은 아래 추천 방향으로 채택했다. 이는 기획 결정을 맡긴 것으로 해석하며, 계산식·기술·상세 동작의 설계나 실제 개발·배포를 요청한 것으로 확대하지 않는다.

### 5.1 개별 답변으로 확정한 사항

| 주제 | 확정한 내용 | 쉬운 예시 |
|---|---|---|
| 1차 범위 | 직접 기록 관리와 수익성·실제 손익·재료 잔량 확인, 저장·백업·복원 우선 | 오늘 판매를 적고 남는 금액과 우유 잔량을 확인 |
| 사용 범위 | 한 매장, 한 사람, 한 기기 | 사장님이 매장 PC 한 대에서 사용 |
| 메뉴 수익성 | 재료비·포장비·결제수수료 포함. 매장 운영비를 메뉴별로 나누지 않음 | 아메리카노의 원두·컵·결제수수료를 고려 |
| 비용의 반영 시점 | 해당 운영 기간 기준 | 7월 월세를 8월에 내도 7월 손익에 반영 |
| 매장 손익의 비용 | 판매에 사용한 재료비·포장비·결제수수료와 운영비·폐기 비용 포함. 재료 구매대금 전체를 추가 비용으로 넣지 않음 | 사용·폐기한 우유 비용을 고려하고 구매대금과 중복하지 않음 |

### 5.2 일괄 요청에 따라 채택한 추천 방향

다음 내용은 자료에서 확인된 사실이 아니라 사용자가 기획 결정을 맡긴 뒤 채택한 운영 요구사항이다.

| 주제 | 채택한 추천 방향 | 쉬운 예시와 추천 이유 |
|---|---|---|
| 실제 재고 | 마감 때 실제로 센 수량에 잔량을 맞추고 차이 기록을 남김 | 기록 3L, 실제 2.5L이면 마감 잔량은 2.5L. 다음 영업부터 실제 수량으로 관리 |
| 원인 미확인 재고 차이 | 1차는 수량과 차이를 관리하고 자동으로 폐기 비용에 넣지 않음 | 부족한 우유가 폐기인지 입력 누락인지 모르면 우선 차이로 남김. 손익에는 이 차이의 금액 영향이 제외됨을 알 수 있어야 함 |
| 과거 기록 | 당시 값 보존. 명시적으로 수정한 기록의 관련 결과는 갱신하되 현재 가격 변경으로 과거 기록을 바꾸지 않음 | 오늘 원두 가격이 바뀌어도 지난달 판매의 당시 원가는 보존. 과거 입력 오류는 수정 가능 |
| 새 판매·폐기 기록의 근거 | 해당 기록 시점의 가격·레시피 등 기준자료를 활용하고 실제 판매가격·할인·수수료를 근거로 기록. 없는 값을 임의로 0이나 추정값으로 채우지 않음 | 필요한 원가 자료가 없으면 확정된 수익성처럼 보이지 않게 함. 세부 원가 적용 방식은 후속 설계 |
| 보관과 이용 장소 | 이용하는 한 기기에서 기록을 보관하고 웹 프로그램을 실행하는 방향 | 사장님 PC에서 다시 열어 이전 기록 확인. 공유·온라인 계정 관리 범위를 줄임 |
| 백업 | 전체 자료를 사용자가 필요할 때 수동으로 따로 보관 | 판매뿐 아니라 레시피와 가격자료도 함께 보관해 결과를 다시 해석할 수 있게 함 |
| 복원 | 백업 시점의 전체 자료로 돌아가며 현재 자료와 합치지 않음. 복원 전 자료도 보존 가능해야 함 | 어제 백업으로 돌아가면 오늘 자료와 중복되지 않음. 복원 뒤 기록은 백업 시점 기준이라는 의미가 명확함 |
| 조회 범위 | 일·월·지정 기간을 1차에 제공. 자료가 일부인 기간과 미마감 상태를 구분 | 9월 실적은 18일 마감까지라는 범위를 알고 조회 |
| 2차 결정 시점 | 엑셀·전망·발주·확장 조회의 구체적 기준은 해당 단계에서 결정 | 1차 핵심 흐름을 먼저 검사하고 2차 기능의 실제 필요에 맞춰 기획 |

## 6. 후속 설계로 남기는 내용

아래는 질문에 대한 답변 대기가 아니라 **이번 PRD에서 정하지 않기로 한 설계 대상**이다. ‘모두 추천’ 요청으로 임의의 계산식이나 기술을 확정하지 않는다.

| 대상 | 아직 정하지 않은 내용 | 다룰 단계 |
|---|---|---|
| 계산 기준 | 새 기록의 원가 적용 방식, 폐기 재료 가격 적용, 수수료 처리, 월 비용의 날짜별 배분, 반올림 등 | 계산 기준 문서 |
| 기록의 상세 처리 | 입력 항목, 중복·오류 처리, 과거 기록 수정과 실제 재고 기준 시점의 관계, 복원 절차 | 상세 기능 설계 |
| 화면 | 화면 구성·배치·색상·표·버튼 등 | 화면 설계 |
| 기술 | 실행 환경, 저장 방법, 백업 파일 형식, 구현 기술과 배포 절차 | 기술 설계 |
| 2차 기능 | 전망 기간과 방법, 부족 판단, 권장 발주량, 주·분기·반기·연간 구분, 엑셀 중복 기록 처리 | 2차 기획 |

원인 미확인 재고 차이의 금액 반영, 직원·기기 간 공유, 자동 백업, 기준자료 편집은 2차 확장 후보로 둔다. 2차 목록은 이번 문서로 모두 구현을 확정한 기능 목록이 아니다.

## 7. 1차 문서 완료 상태

- 핵심 흐름과 1차·2차 범위를 구분했다.
- 자료에서 확인한 사실과 사용자 선택·채택한 추천 방향을 구분했다.
- 1차의 주요 운영 의미, 결과 중심 검사 기준, 4시간 목표 배분을 정리했다.
- 계산식·화면 디자인·기술·상세 동작·코드는 정하지 않았다.
- 이 문서는 PRD 완료 상태다. 프로그램 개발·검사·배포는 아직 수행하지 않았다.
