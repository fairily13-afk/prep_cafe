## 1. 사용 흐름과 기능 범위

한 매장, 한 사람, 한 기기에서 사용한다. 기본 흐름은 **판매 입력·저장 → 메뉴 수익성 확인 → 같은 기간의 매장 손익 확인 → 재료 잔량 확인**이다. 비용·입고·폐기·실제 재고 기록은 같은 흐름의 결과에 연결된다.

1차는 기존 메뉴 8개·재료 11개·레시피 등 기준자료를 이용한다. 판매·비용 입력·수정·삭제, 입고·폐기·마감 실측 기록, 일·월·지정 기간 조회, 기록 보관, 전체 수동 백업·복원을 제공한다. 무료 시음·직원 복지·주문별 기록·환불 처리는 별도 기능으로 추가하지 않는다.

예상 손익, 부족 경고·소진 예측·권장 발주, 엑셀 입력 양식·가져오기, 확장 기간 조회, 기준자료 편집 등은 PRD대로 2차 후보다. POS 연동·증빙 첨부·반복 비용·손익분기점 분석·보고서 인쇄·분석용 엑셀 내보내기는 시안에 있지만 1차 승인 기능이 아니다.

## 2. 시안과 PRD의 차이 및 처리

시안은 네 개의 화면과 팝업을 포함한다. 시안 코드에는 일부 계산 미리보기·필터·팝업 열기만 구현되어 있다. 저장 버튼이 창을 닫는 동작을 실제 기록 저장으로 해석하지 않는다. 고정 표시된 날짜·금액·메뉴·재고 수치도 실제 자료의 값이 아니다.

### 2.3 시안에 빠진 필수 요소

판매 수정·삭제(F04·F05), 폐기 입력(F11), 일·월·시작일/종료일 조회(F02), 실제 단가·할인·수수료·판매채널(F03), 저장 상태(F14), 전체 백업·복원(F15·F16)을 보완한다. 이는 신규 범위가 아니라 PRD 필수 기능의 누락을 채우는 것이다. 재고 이벤트 수정·삭제, 직원 권한, 자료 초기화 버튼은 새 기능으로 추가하지 않는다.

## 3. 공통 입력·처리·결과 기준

다음은 기존 기능을 구현하기 위한 추천 상세 기준이다.

- 날짜는 매장 기준의 하루를 뜻한다. 시작·종료일은 모두 포함한다. 판매는 주문 한 건이 아니라 날짜·메뉴·채널별 기록이다.
- 빈칸은 0이 아니다. 단가·할인·수수료에서 실제 0은 허용하되 미입력 값과 구분한다. 수량은 판매의 경우 1 이상의 정수, 재료의 경우 기준단위의 양수(실측은 0 이상)다.
- 저장 전 잘못된 입력을 알려준다. 새 기록의 대상 메뉴·재료·공급사가 없거나 단위가 다르면 저장하지 않는다.
- 원가 기준만 부족한 유효 기록은 ‘원가 미완성’으로 보관할 수 있다. 확인된 매출·수량은 표시하지만 미완성 수익성·손익은 확정 숫자처럼 표시하지 않는다. 잘못된 참조·수량과 원가 누락을 구분한다.
- 수정·삭제는 대상 기록 번호로 처리한다. 목록의 순서나 행 번호를 기록의 신원으로 사용하지 않는다.
- 저장 성공 후만 목록·요약·관련 손익·재고를 함께 갱신한다. 저장 중 연속 클릭을 막는다. 저장 실패 시 이전 자료와 입력 내용을 유지하고 재시도 방법을 안내한다.
- 취소·닫기는 저장하지 않는다. 입력 변경이 있을 때 나가기 전 폐기 여부를 확인한다. 삭제에는 날짜·대상·수량 또는 금액을 보여주고 확인한다.
- 확인된 합계와 미완성 기록 수를 함께 보여준다. 일부 기록을 빼고 계산한 값을 전체 합계처럼 표현하지 않는다.
- 판매일의 기록 저장 자체가 영업일 전체의 마감 완료를 의미하지 않는다. 기존 달력의 마감 정보를 표시하고, 새 날짜나 수정된 날짜는 ‘마감 확인 필요’로 구분한다. 독립적인 마감·잠금 기능은 추가하지 않는다.
- 재료 잔량은 여러 날짜의 잔량을 더하지 않고 조회 종료일 마감 시점 수량을 본다.
- 일상 저장은 기기에 기록을 보관하는 처리다. 사용자 파일은 전체 백업 또는 복원 전 백업 때만 만든다. 조회만으로 파일을 생성하지 않는다.

## 4. 계산 방법 제안

PRD에서 확정한 비용 의미를 유지하는 추천 계산 기준이다. 표시용 반올림 전 값을 집계하며, 어떤 화면에서도 같은 기준을 사용한다. `합계`는 해당 조회 기간의 대상 기록을 더한다는 뜻이다.

### C01 판매 기록과 메뉴 수익성

| 결과 | 추천 계산 방법 |
|---|---|
| 할인 전 판매금액 | 판매수량 × 실제 개당 판매단가 |
| 할인 후 매출(순매출) | 할인 전 판매금액 − 해당 기록 전체의 할인금액 |
| 기록의 재료비·포장비 | 각각 판매수량 × 당시 개당 재료원가·개당 포장원가 |
| 기록의 메뉴 이익 | 할인 후 매출 − 재료비 − 포장비 − 기록 전체 결제수수료 |
| 메뉴 판매수량·매출·메뉴 이익 | 같은 메뉴의 매장·포장 기록을 해당 기간에서 각각 합산 |
| 개당 평균 판매금액·원가·메뉴 이익 | 각 기간 합계 ÷ 해당 메뉴 판매수량. 현재 기준 판매가로 대체하지 않음 |
| 메뉴 이익률 | 메뉴 이익 합계 ÷ 할인 후 매출 합계 × 100 |
| 전체 메뉴 이익률 | 전체 메뉴 이익 합계 ÷ 전체 할인 후 매출 합계 × 100. 메뉴별 비율의 단순 평균은 사용하지 않음 |

할인은 개당 금액이 아닌 기록 전체 할인으로 입력한다. 결제수수료도 기록 전체 실제 금액으로 입력하며 임의 수수료율을 적용하지 않는다. 매출 0이면 이익률은 ‘계산 불가’, 판매수량 0이면 개당 평균은 ‘판매 없음’이다. 음수 메뉴 이익은 손실로 그대로 보여준다.

예: 아메리카노 10개, 개당 4,000원, 전체 할인 1,000원, 전체 수수료 600원, 개당 재료원가 460원, 포장원가 0원이면 할인 후 매출은 39,000원, 재료비는 4,600원, 메뉴 이익은 33,800원, 이익률은 약 86.7%다. 무료·시음 관리 기능을 추가하는 예는 아니다.

### C02 새 기록의 원가와 과거 보존

- 재료별로 기록일 이전 또는 당일에 적용 시작한 가격 중 가장 최근 가격을 선택한다. 같은 재료·같은 시작일의 가격이 둘 이상이면 임의로 하나를 선택하지 않고 원가 미완성으로 표시한다.
- 기준단위당 가격 = 구매가격 ÷ 구매용량. 구매용량은 0보다 커야 하며 레시피 단위와 맞아야 한다. 해당 날짜의 가격이 없으면 최초가격을 임의로 소급 적용하지 않는다.
- 새 판매 개당 원가는 적용 레시피의 ‘메뉴 한 개당 사용량 × 재료 기준단위당 가격’을 합산한다. `channel_only`가 비어 있으면 양 채널, 포장이면 포장 판매에만 포함한다. 포장 전용 재료의 원가는 포장비, 공통 재료는 식재료비로 구분하는 것을 추천한다. 이 자료의 포장 전용 레시피 구조를 이용하는 규칙이며 다른 자료에 무조건 일반화하지 않는다.
- 계산에 사용한 개당 원가·레시피 버전과 가격 근거를 판매 당시 기록으로 보관한다. 입고단가 입력이 가격이력 편집이나 과거 원가 변경을 자동으로 일으키지 않는다.
- 기존 판매는 파일에 기록된 순매출·수수료·개당 원가를 당시 기록으로 사용한다. 새 계산과 다르더라도 원본을 자동으로 덮어쓰지 않고 불일치를 알려준다.
- 과거 판매의 수량·단가·할인·수수료만 수정하면 기존 개당 원가는 유지하고 변경된 입력이 영향을 주는 결과만 갱신한다. 날짜·메뉴·채널·레시피 적용 대상이 달라지면 변경된 시점·대상 기준의 원가를 새로 산출하되, 수정 대상 밖의 과거 기록은 바꾸지 않는다.

### C03 비용과 운영 손익

운영비는 비용기록의 귀속일별 금액을 합산한다. 초기 월비용계획은 참고자료로 보관하며 비용기록에 다시 더하지 않는다. 1차에서 새 운영비도 귀속일별 금액으로 기록한다. 월 금액을 나누어 입력해야 할 경우의 추천 배분 기준은 **그 달의 달력 날짜 수에 따른 균등 배분**이며 휴무일도 포함한다. 기존 일별 배분값은 재배분하지 않는다. 월 비용 일괄 입력·자동 생성 기능을 새로 추가하지 않는다.

월 금액을 일별 원 단위로 나누는 기준: 각 날짜에 기본 정수 금액을 배분하고, 남은 원은 그 달의 앞 날짜부터 1원씩 배분하여 월 합계를 보존한다. 나중에 특정 귀속일 금액을 수정해도 다른 날짜가 자동으로 바뀌지 않는다.

- 폐기 비용 = 버린 수량의 절댓값 × 폐기일의 기준단위당 재료 가격. 기존 폐기 189건에는 단가가 없으므로 C02의 가격이력으로 평가한다. 새로 평가한 금액은 원본의 과거 확정값이라고 표시하지 않는다. 평가에 사용한 가격을 보관하여 조회할 때 임의로 달라지지 않게 한다.
- 운영 손익 = 할인 후 매출 합계 − 판매에 쓴 재료비 − 포장비 − 결제수수료 − 운영비 − 폐기 비용.
- 운영 손익률 = 운영 손익 ÷ 할인 후 매출 합계 × 100. 매출 0이면 비율은 계산 불가다.
- 재료 구매대금 전체와 원인 미확인 실사 차이의 금액은 이 손익에 추가하지 않는다. 결제수수료를 운영비로 다시 입력하거나 재료 구매를 운영비로 입력해 중복 계산하지 않는다.
- 소모품·청소비 중 레시피 포장비와 겹치는 지출은 중복이다. 가격이 비슷하다는 이유로 자동 삭제하지 않고 이미 원가에 포함된 비용인지 입력 안내로 구분한다.
- 폐기 가격·원가·비용 기록이 빠지면 손익은 ‘미완성’이다. 확인 가능한 항목 소계와 누락 대상을 보여준다. 원인 미확인 재고 차이의 금액 영향 제외 사실은 정상 계산에서도 표시한다.
- 원가 평가 결과는 소수 원 단위를 보존해 합산하고 화면에서만 원 단위 반올림한다. 비율은 소수 첫째 자리, g·ml 수량은 필요한 소수 자릿수, 개 수량은 정수로 표시한다. 백업에는 표시 반올림 전 값과 근거를 보관한다.

### C04 재료 사용과 마감 잔량

- 판매 재료 사용량 = 판매수량 × 판매에 적용되는 레시피의 메뉴 한 개당 재료 사용량. 매장 판매에는 포장 전용 재료를 차감하지 않는다.
- 실측이 없는 구간의 잔량 = 구간 시작 잔량 + 입고 − 판매 사용량 − 폐기량. 실측 이전부터 계산한다면 초기재고가 출발점이다.
- 같은 날 처리 순서 추천: 시작 잔량 → 그날 입고·판매·폐기 → 마감 실측. 이 자료는 시간 정보가 없으므로 영업 중 시간별 잔량을 계산하지 않는다.
- 마감 실측이 있으면 해당 재료의 그날 최종 잔량은 실측수량이다. 실사 차이 = 실측수량 − 실측 직전 기록상 잔량. 이 차이를 다시 더하고 실측수량도 더하는 중복 처리는 하지 않는다.
- 같은 재료·같은 날짜의 마감 실측은 한 기준값만 인정한다. 새 실측이 기존 마감 실측과 겹치면 중복 저장을 막고 기존 기록이 있음을 알린다. 재고 수정·삭제 기능은 1차에 별도 추가하지 않는다.
- 과거 판매·입고·폐기 변화는 이후 잔량과 다음 실측 직전 차이에 반영하되 실제로 센 절대수량을 바꾸지 않는다. 실측 뒤 구간은 해당 실측수량에서 다시 이어진다. 가져온 실사 증감값과 재계산 차이가 다르면 원본 값은 보존하고 차이를 안내한다.
- 초기재고·레시피·단위가 빠져 잔량 계산이 불가능하면 ‘계산 불가’로 표시한다. 기록상 음수 재고는 실제로 음수 재료가 있다는 뜻이 아닌 기록 오류 가능성으로 알리고 0으로 숨기지 않는다.

## 5. 기능별 요구사항

각 항목의 처리·검사 방식은 3·4절의 추천 상세 기준을 따른다. 화면 명칭은 역할을 뜻하며 세부 배치나 새 디자인을 확정하지 않는다.

### F01 초기 자료 이용 — PRD R01

- 사용자가 처음 프로그램을 이용한다.
- 기존 보관 자료가 없는 정상 상태에서 제공 JSON 샘플을 한 번만 초기 자료로 준비한다. 모든 종류의 기록·기준자료·출처·기간을 함께 확인한다. 파일 업로드 기능을 추가하는 뜻이 아니다.
- 저장 상태·기록 수·매장명·가상 샘플·부가세 제외·마감 기준일을 보여준다. 이후 다시 열면 사용자가 보관한 기록을 읽으며 샘플을 중복 추가하지 않는다.
- 원본 파일은 수정하지 않는다. 자료가 깨짐·중복 번호·알 수 없는 참조·잘못된 단위를 포함하면 문제 항목을 알리고 초기 준비를 완료하지 않는다. 기존 자료가 읽히지 않는 상황을 최초 이용으로 오해해 샘플로 교체하지 않는다.

### F02 기간 조회 — PRD R06

- 일자, 월 또는 시작·종료일을 선택하면 해당 날짜를 포함하는 판매·비용·폐기 기록과 종료일 마감 재고를 조회한다. 월 이전/다음도 같은 기능이다.
- 같은 조회 기간이 메뉴 수익성과 손익에 적용된다. 새 기록 저장으로 기간 자체가 임의로 바뀌지 않는다.
- 조회 기간, 실제 기록 범위, 마지막 마감일, 미완성 여부를 표시한다. 미래·미마감 구간은 실적 0으로 채우지 않는다. 기간 변경은 보관 기록을 바꾸거나 파일을 생성하지 않는다.
- 시작일이 종료일 뒤면 조회하지 않고 날짜 수정을 요청한다. 초기재고 이전 재고 조회는 계산 불가다. 자료가 없는 기간은 ‘기록 없음’, 완료된 영업일에서 확인된 0은 ‘0’, 미마감은 ‘미마감’으로 구분한다.

### F03 판매 입력 — PRD R02

- 입력: 판매일, 기존 메뉴, 매장/포장 채널, 수량, 실제 개당 단가, 기록 전체 할인, 기록 전체 실제 결제수수료. 레시피 버전·개당 원가·순매출은 자료와 C01·C02로 확인하는 파생값이다. 기준 판매가는 입력 참고값이지 실제 단가 확정값이 아니다.
- 날짜·메뉴·채널·수량 등이 유효하면 저장 전 할인 후 매출·원가·메뉴 이익을 미리 보여준다. 입력을 바꾸면 미리보기도 바뀌며 이 단계는 기록 저장이 아니다.
- ‘판매 기록 추가 및 장부 반영’을 누르면 판매번호를 부여해 보관하고 관련 기간 메뉴 수익성·손익·재료 사용을 갱신한다. 목록에서 저장된 기록을 확인한다. 별도 사용자 파일은 만들지 않는다.
- 필수값 누락, 날짜 형식 오류, 수량 0·음수·소수, 음수 단가·할인·수수료, 할인 전 금액보다 큰 할인은 저장하지 않는다. 수수료가 순매출보다 크면 손실 가능성을 확인시키고 실제 값이면 보존하는 것을 추천한다.
- 같은 날짜·메뉴·채널 기록이 있으면 별도 행을 자동 추가하거나 자동 합산하지 않는다. 기존 기록을 확인해 F04에서 수정하도록 안내한다. 저장 실패·중복 클릭은 중복 기록을 만들지 않는다.
- 존재하는 메뉴지만 원가 자료가 부족하면 3절대로 원가 미완성 기록을 보관하고 관련 결과의 미완성 상태를 보여준다. 달력에 없는 판매일은 판매 입력을 허용하되 마감 확인 필요로 표시한다. 기존 휴무일에 판매 입력 시 날짜 확인을 요구한다.

### F04 판매 수정 — PRD R02

- 판매 목록에서 수정할 기록을 선택한다. 기존 입력값을 보여주고 F03의 입력값을 고친 뒤 저장한다.
- 같은 판매번호의 기록을 변경하고 C02의 보존·재평가 기준에 따라 관련 메뉴 수익성·손익·재료 사용·이후 재고를 갱신한다. 날짜를 바꾸면 이전 기간과 새 기간 모두 갱신한다. 다른 과거 기록은 덮어쓰지 않는다.
- 다른 판매의 날짜·메뉴·채널과 겹치면 저장하지 않는다. 수정 대상이 없거나 화면을 연 뒤 자료가 복원되어 달라졌다면 이전 자료에 덮어쓰지 말고 다시 조회하도록 안내한다.
- 취소 또는 저장 실패 시 기존 기록을 유지한다. 원가 미완성 상태가 생기면 알려준다.

### F05 판매 삭제 — PRD R02

- 판매 목록의 삭제를 누르면 대상 날짜·메뉴·채널·수량을 보여준다. 취소하면 변경하지 않는다.
- 확인 후 해당 판매만 제거하고 그 판매의 매출·원가·수수료·재료 사용 영향을 관련 결과에서 제거한다. 이후 실측수량은 C04대로 보존한다.
- 이미 없는 기록이면 삭제됐음을 알려 새로 조회한다. 삭제 보관 실패 시 목록에서만 숨기지 않고 이전 기록을 유지한다. 삭제 취소 복구 기능은 추가하지 않는다. 전체 백업 복원은 F16이다.

### F06 메뉴 수익성 조회 — PRD R03

- 조회 기간의 메뉴별 수량, 할인 후 매출, 재료비·포장비·수수료, 메뉴 이익과 이익률을 C01로 표시한다. 개당 값은 해당 기간 평균이라고 명시한다.
- 시안의 메뉴명 검색·실제 분류 선택·수량/메뉴 이익/이익률 정렬은 기존 목록 조회를 돕는 방식으로 사용한다. 필터 적용 후 소계는 ‘선택 결과’, 전체 기간 합계는 ‘전체’라고 구분한다.
- 저장된 판매 변화가 결과에 반영된다. 계산 근거의 원가 누락·분모 0은 0%나 정상 이익처럼 표시하지 않는다. 판매량·매출이 0인 메뉴는 판매 없음으로 구분한다.
- ‘효자·위험·목표 달성’ 등 임의 등급은 부여하지 않는다. 음료·디저트 수량을 합친 값을 모두 ‘잔’이라고 표시하지 않고 ‘판매수량’으로 표현한다. 파일 출력은 없음.

### F07 운영비 입력·목록 — PRD R04

- 입력: 귀속일, 기존 비용항목, 부가세 제외 금액. 그 비용이 해당하는 운영일을 선택하며 결제일·월 계획은 자동 비용으로 추가하지 않는다.
- 저장을 누르면 비용번호를 부여해 보관하고 목록·항목별 합계·F09 손익을 갱신한다. 귀속일·항목·금액이 화면 결과다. 날짜·비용항목 검색과 페이지 이동은 목록을 찾는 보조 동작이다.
- 금액은 0 이상 정수 원으로 입력한다. 빈칸·음수·잘못된 날짜·없는 항목은 저장하지 않는다. 같은 날짜·항목의 여러 비용은 허용하되 동일 날짜·항목·금액의 기록이 있으면 중복 가능성을 알리고 추가 여부를 확인한다. 이미 날짜별 배분된 월세 등을 다시 기록하면 중복이라는 안내가 필요하다.
- 판매 원가에 포함된 재료·포장 구매나 결제수수료를 다시 운영비로 넣는 방식은 제공하지 않는다. 영수증·결제수단·거래처 관리는 추가하지 않는다. 일상 입력으로 파일 생성 없음.

### F08 운영비 수정·삭제 — PRD R04

- 목록의 수정은 기존 귀속일·항목·금액을 불러와 고친 후 같은 비용번호에 저장한다. 삭제는 대상 귀속일·항목·금액 확인 후 제거한다.
- 비용의 이전 기간·새 기간 합계와 운영 손익을 갱신한다. 판매 개당 원가·재료 수량은 바꾸지 않는다. 월비용계획은 수정하거나 다시 배분하지 않는다.
- 잘못된 입력·없는 대상·취소·저장 실패는 F04·F05와 같은 보존 기준으로 처리한다. 페이지 마지막 행 삭제 후 유효한 페이지로 이동하고 페이지 합계와 전체 합계를 구분한다.

### F09 실적·운영 손익 조회 — PRD R04·R06

- 기간을 선택하거나 연결된 기록을 저장하면 C03의 항목별 금액과 운영 손익을 보여준다. 할인 전 판매액과 할인 후 매출은 혼동하지 않게 구분한다.
- 화면 결과: 선택 기간·실제 기록 범위·마감 상태, 매출·사용 재료비·포장비·수수료·운영비·폐기 비용·운영 손익, 원인 미확인 재고 차이 금액 제외 안내. 임차료·인건비 등 운영비 내역은 기존 비용항목 기준이다.
- 손실은 음수로 표시한다. 미래 전망·목표 달성·전월 증감·손익분기점은 계산하지 않는다. 불완전한 기록이 있으면 누락 근거·확인 가능한 소계와 함께 손익 미완성을 표시한다. 파일 출력 없음.

### F10 입고 기록 — PRD R05

- ‘입고 등록’ 또는 상단 입고를 누르고 기존 재료, 입고일, 재료 기준단위의 입고량, 기준단위당 입고단가를 입력한다. 기존 공급사 정보와 단위를 확인한다. 구매용량 전체 가격을 기준단위당 가격으로 오해하지 않도록 단가 단위를 표시한다.
- 입고 완료를 누르면 입고번호·일자·재료·양수 증감량·기준단위·단가·공급사를 보관한다. 재고 목록의 잔량·최근 입고 정보를 갱신한다. 입고금액(수량 × 단가)은 입고 참고값이며 손익 운영비에 자동 추가하지 않는다.
- 알 수 없는 대상, 기준단위 불일치, 수량 0 이하, 단가 음수·빈칸은 저장하지 않는다. 중복 제출을 막는다. 같은 날 여러 입고는 허용하되 같은 재료·수량·단가가 반복되면 중복 가능성을 확인한다. 신규 재료·공급사 생성은 없음.

### F11 폐기 기록 — PRD R05·R04

- 시안에 빠진 폐기 입력을 보완한다. 기존 재료, 폐기일, 버린 기준단위 수량, 사유를 입력한다. 사용자는 양수량을 입력하고 보관 증감량은 음수로 구분한다.
- 저장하면 재고 이벤트와 C03의 평가 근거·폐기 비용을 보관한다. 재고에서 한 번 차감하고 운영 손익에서 한 번 비용으로 반영한다. 판매·실사조정과 중복 비용을 만들지 않는다.
- 수량 0 이하·잘못된 단위·없는 재료·날짜 오류는 저장하지 않는다. 폐기 후 기록상 잔량이 음수가 되면 기록 확인을 요청하되 실제 폐기를 없었던 것으로 숨기지 않는다. 폐기일 가격이 없으면 수량 기록은 원가 미완성 상태로 보관하고 폐기 비용·손익 미완성을 알린다. 파일 출력 없음.

### F12 마감 실제 재고 입력 — PRD R05

- 기존 재료를 선택해 실측일, 마감 때 실제로 센 기준단위 수량, 조정 사유를 입력한다. 선택 메모는 사유 기록의 설명으로 활용하는 추천이다.
- 실측 직전 기록상 잔량과 실제 수량·차이를 확인하고 저장한다. 마감 잔량은 C04대로 실측수량이며 실측 기록과 차이 근거를 보존한다. 실사 차이는 자동으로 폐기 비용에 넣지 않는다.
- 실제 수량 0은 허용하고 음수·빈칸·단위 불일치는 거절한다. 같은 날짜·재료 마감 실측 중복은 저장하지 않는다. 여러 재료를 합쳐 하나의 수량으로 기록하지 않는다. 시안의 ‘일괄 점검’ 버튼은 기존 재료 하나를 선택하는 입력으로 연결한다.
- ‘유통기한 폐기’를 실사 사유로 선택해도 자동 폐기 이벤트는 생성하지 않는다. 실제 폐기는 F11로 따로 기록하고 실측은 그날 최종 재고를 뜻한다. 전산 잔량이 계산 불가라도 실제 수량은 기록할 수 있으나 차이는 계산 불가로 표시한다.

### F13 재료 잔량 조회 — PRD R05

- 조회 기준일까지 초기재고·판매 레시피·입고·폐기·실측을 C04로 연결한다. 시안의 ‘현재 실재고’ 표시는 실제로 센 시점의 값인지 기록상 추정인지 구분한다.
- 화면 결과: 기존 재료명·기준단위·종료일 마감 잔량·마지막 실측일/수량·기록상 차이·최근 입고 정보. 재료명 검색과 목록 이동으로 확인한다. 서로 다른 재료의 g·ml·개를 합친 전체 수량은 표시하지 않는다.
- 음수 잔량·누락 초기재고·없는 레시피·단위 오류는 정상 수량과 구분한다. 시안의 kg·팩·병 수량을 자동 적용하지 않고 자료 기준단위를 사용한다. 안전재고·유통기한·소진일수·발주량 계산은 없음. 파일 출력 없음.

### F14 저장과 재이용 — PRD R07

- 판매·비용·재고 기록 저장은 해당 기기에 보관한다. 저장 완료 상태는 보관 처리 성공 후에만 표시한다. 프로그램을 다시 열면 보관한 최신 기록을 읽어 같은 결과를 보여준다.
- 저장 중 새 저장·복원은 겹치지 않게 처리한다. 저장 실패·저장공간 부족·자료 읽기 실패를 정상 빈 자료로 취급하지 않는다. 입력은 가능한 범위에서 화면에 유지하고 백업·재시도 안내를 제공한다.
- 같은 기기라도 다른 브라우저·사용자 프로필·다른 프로그램 주소에서는 별도 자료일 수 있다. 자세한 저장 방식은 TRD에서 설명한다. 자동 파일 백업·서버 공유는 제공하지 않는다.

### F15 전체 수동 백업 — PRD R08

- 전체 백업을 요청하면 저장된 일관된 시점의 매장 자료를 하나의 JSON 파일로 내려받는 것을 추천한다. 아직 저장하지 않은 입력은 포함하지 않으며 그 사실을 알린다.
- 포함: 모든 판매·비용·재고·초기재고, 메뉴·재료·공급사·레시피·가격이력·달력·월비용계획·자료정보, 당시 원가와 폐기 평가 근거, 운영 설정. 백업 형식 버전·계산 기준 버전·생성 시각·기록 종류별 수를 포함한다.
- 파일명 제안: `prep-cafe-backup-YYYYMMDD-HHmmss.json`. 생성 시각은 한국시간을 표시하며 내부에는 시간대 정보를 함께 보관한다. 이는 엑셀 기록 가져오기나 분석 보고서가 아니다.
- 저장 중이면 완료를 기다린 후 백업한다. 파일 생성·다운로드 준비 실패 시 현재 기록은 유지한다. 브라우저가 파일을 실제로 사용자 폴더에 저장했는지는 프로그램이 보장할 수 없으므로 파일 존재 확인을 안내한다. 취소 시 매장 자료 변화 없음.

### F16 전체 복원 — PRD R08

- 전체 백업 파일을 선택하면 내용·형식 버전·매장·기준일·종류별 수·당시 계산 기준을 먼저 검사하고 현재 자료를 대체한다는 결과를 보여준다. 제공 원본 JSON이나 엑셀은 이 백업 형식과 다르므로 직접 복원 파일로 취급하지 않는다.
- 현재 자료의 전체 백업을 먼저 준비하고 사용자가 확인한 후 복원한다. 복원 취소·검사 실패는 현재 자료를 바꾸지 않는다.
- 복원 성공 시 전체 기록·기준자료·설정을 백업 상태로 함께 대체한다. 현재 자료와 합치지 않고 샘플을 다시 넣지 않는다. 목록·기간·손익·재고는 복원된 자료 기준으로 갱신하고 복원 완료·백업 기준 시각을 표시한다.
- 깨진 JSON·필수 자료 누락·중복 번호·알 수 없는 참조·지원하지 않는 버전·금액이나 단위 오류는 복원하지 않는다. 원가 미완성이라는 정상 상태 자체는 복원 오류가 아니다.
- 복원 전 백업 준비 실패나 쓰기 실패면 복원을 중단하고 이전 자료를 유지한다. 중간에 일부 종류만 바뀐 상태를 성공으로 처리하지 않는다. 비정상 종료 후 다시 열어도 이전 완전 자료 또는 새 완전 자료 중 하나를 이용해야 한다.

| R02 판매 관리 | F03·F04·F05 | 입력·수정·삭제가 메뉴 실적·손익·재료 사용에 함께 반영 |

## 7. 결정 기록과 남겨둔 범위

- 사용자 확인: PRD 우선 A안, 시안의 추가 기능을 1차에서 제외. 누락된 PRD 필수 기능은 보완.
- 기존 대화와 문서 완성 요청에 따라 본 문서의 입력·계산·오류 대응을 추천 상세 기준으로 정리했다. TRD에서 임의의 다른 계산 방식으로 바꾸지 않는다.
